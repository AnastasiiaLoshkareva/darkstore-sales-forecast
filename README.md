# Прогноз недельных продаж дарксторов: обучение, PSI-мониторинг и батч-инференс в Airflow

> **Учебный контекст:** Яндекс Практикум, программа Data Science, модуль 5 («Пакетное внедрение для сети дарксторов»): исследовательская часть и практическая часть (DAG в Airflow).

Учебный проект: система прогнозирования недельных продаж по отделам для сети дарксторов «Прилавок» (Store × Dept × неделя). Модель CatBoost обучена в Jupyter, сохранена в S3, а еженедельный батч-инференс автоматизирован в Apache Airflow с записью результата в PostgreSQL.

## Бизнес-задача

Планирование закупок по субъективным оценкам аналитиков ведёт к дефициту товаров в пик и к избыточным запасам. Цель проекта: получить автоматический прогноз недельных продаж (`weekly_sales`, руб.) для каждого отдела каждого даркстора на плановый период.

**Режим работы:** пакетный (batch) с недельным циклом. DAG загружает актуальную модель из S3, считает признаки для планового периода и пишет прогнозы в PostgreSQL.

## Результаты

Валидация по времени: обучение февраль 2023 — август 2025 (383 541 строка), валидация сентябрь — октябрь 2025 (23 647 строк).

| Метрика | Обучение | Валидация |
|---------|----------|-----------|
| MAE | 1 803.54 | 1 496.25 |
| RMSE | 4 550.41 | 3 196.17 |
| R² | 0.9602 | 0.9785 |

Качество на валидации не хуже, чем на обучении, признаков переобучения нет (ранняя остановка на итерации 216).

## Данные

Источник: PostgreSQL. Данные о продажах за февраль 2023 — октябрь 2025.

- `sales`: `store` (1–45), `dept` (1–99), `date` (начало недели), `weekly_sales` (целевая переменная), `is_holiday`.
- `stores`: `store`, `type` (A, B, C), `size`.
- `features`: внешние факторы по неделе: `temperature`, `fuel_price`, `cpi`, `unemployment`, `factor1`–`factor5` (признаки акций и скидок).
- `plan`: данные для инференса (ноябрь 2025 — июль 2026), те же столбцы, что в `sales`, кроме `weekly_sales`.

**Обработка аномалий и пропусков.** Данные проверены на дубликаты и пропуски (функция `explore_data` в ноутбуке). Отрицательные продажи (возвраты) заменяются на пропуск, чтобы они не искажали средние и лаги. Пропуски в колонках `features` при обучении заполняются нулём; в `preprocessing.py` (инференс) пропуски в числовых признаках, кроме целевой, заполняются средним.

## Признаки

- Временные: месяц, квартал, год.
- `avg_sales_before`: накопительное среднее продаж по паре (store, dept) до текущей недели.
- Лаги продаж: `sales_1week_ago`, `sales_2week_ago`, `sales_4week_ago`.
- Скользящие средние: `mean_sales_2week`, `mean_sales_4week`.

Все признаки по продажам считаются со сдвигом, то есть используют только информацию, доступную на момент прогноза (нет утечки данных).

## Мониторинг стабильности признаков (PSI)

Выборка делится по времени (обучение до сентября 2025, валидация сентябрь — октябрь 2025), PSI считается для каждого числового признака между выборками.

| Признак | PSI | Статус |
|---------|-----|--------|
| month | 19.66 | сильный дрейф |
| year | 17.05 | сильный дрейф |
| fuel_price | 11.80 | сильный дрейф |
| quarter | 11.83 | сильный дрейф |
| temperature | 3.12 | сильный дрейф |
| unemployment | 1.46 | сильный дрейф |
| cpi | 1.04 | сильный дрейф |
| factor2 | 0.45 | сильный дрейф |
| factor1 | 0.33 | сильный дрейф |
| factor4 | 0.28 | сильный дрейф |
| factor5 | 0.14 | умеренный дрейф |
| factor3 | 0.12 | умеренный дрейф |
| size, avg_sales_before, лаги и скользящие средние | < 0.01 | стабильны |

Дополнительно: PSI целевой переменной `weekly_sales` равен 0.0015 (распределение не изменилось), PSI по `store` и `dept` меньше 0.02 (структура сети не изменилась).

**Решение.** Признаки с PSI ≥ 0.2 (`month`, `quarter`, `year`, `temperature`, `fuel_price`, `cpi`, `unemployment`, `factor1`, `factor2`, `factor4`) удалены из обучения. Причины дрейфа: сезонность (в обучении февраль — август, в валидации сентябрь — октябрь), трендовые макропоказатели (`cpi`, `unemployment`), неравномерность акций по времени. Признаки с умеренным дрейфом (`factor3`, `factor5`) оставлены.

## Обучение модели

`CatBoostRegressor`: `iterations=1000`, `learning_rate=0.05`, `depth=6`, `loss_function='RMSE'`, `early_stopping_rounds=50`, `random_seed=42`. Категориальные признаки: `store`, `dept`, `type`, `is_holiday`. Подбор гиперпараметров не проводился.

Самые важные признаки: `sales_1week_ago`, `mean_sales_4week`, `mean_sales_2week`, `sales_4week_ago`, `avg_sales_before`. Тип и размер даркстора вносят наименьший вклад.

Модель сохраняется в S3 как `catboost_model.pkl`.

## Архитектура пайплайна (DAG `sales_prediction_batch_inference`)

Расписание: раз в неделю (`0 20 * * 0`).

```
load_data ──► preprocess_features ──┐
                                    ├──► run_inference ──► save_predictions
load_model ─────────────────────────┘
```

| Задача | Что делает |
|--------|-----------|
| `load_data` | Через `PostgresHook` создаёт временную таблицу `inference_data_temp` (история `sales` + плановые данные `plan` + `stores` + `features`), логирует число строк и границы дат, передаёт в XCom первую дату плана |
| `preprocess_features` | Читает временную таблицу, вызывает `preprocess_data` из `preprocessing.py`, оставляет строки плана, удаляет `weekly_sales`, заполняет нулями лаги первых недель, удаляет остаточные NaN, передаёт данные в XCom и удаляет временную таблицу |
| `load_model` | Скачивает модель из S3 во временный файл, путь передаёт в XCom |
| `run_inference` | Загружает признаки и модель, считает прогноз (`predicted_weekly_sales`), отрицательные значения заменяет нулём |
| `save_predictions` | Создаёт таблицу `predictions` и записывает прогнозы с upsert (`ON CONFLICT DO UPDATE`), выводит число строк и первые 5 строк |

**Где что хранится:** модель в S3 (Yandex Object Storage), прогнозы в таблице `predictions` в PostgreSQL. Креды в коде отсутствуют: подключение к БД через Airflow Connection, ключи S3 через Airflow Variables.

## Запуск

### 1. Обучение (ноутбук)

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить своими значениями
jupyter notebook model_training.ipynb
```

### 2. Настройка Airflow

Окружение: Airflow 2.9.2, Python 3.12.

```bash
pip install -r requirements-airflow.txt
```

Airflow Variables (Admin → Variables):

- `s3_bucket_name`: имя бакета;
- `s3_model_key`: путь к модели в бакете (`catboost_model.pkl`);
- `s3_access_key`, `s3_secret_key`: ключи доступа S3.

Airflow Connection (Admin → Connections):

- Conn Id `postgres_sales_db`, тип Postgres, поля Host, Schema, Login, Password, Port из параметров вашей БД.

### 3. Запуск DAG

Положить файлы из `dags/` в каталог DAG Airflow, запустить `sales_prediction_batch_inference` (Trigger DAG) и проверить таблицу результатов:

```sql
SELECT COUNT(*), MIN(date), MAX(date) FROM predictions;
```

## Ограничения

- Валидационное окно короткое (сентябрь — октябрь 2025, 8 недель), оценка сезонности ограничена.
- Из-за удаления `month`, `quarter` и `year` модель не использует календарную сезонность напрямую. Дрейф этих признаков во многом вызван выбором окна валидации, а не изменением поведения продаж.
- Подбор гиперпараметров и сравнение с другими моделями не проводились.
